# Architecture Generic Timer Driver — Kuberve

Этот модуль реализует драйвер системного таймера, встроенного непосредственно внутри ядер архитектуры ARMv8-A. Он отвечает за генерацию фиксированных временных интервалов (тики ОС), необходимых для переключения контекста задач планировщиком (Scheduler).

## Структура файлов модуля

* `timer.h` — Описание интерфейса таймера (инициализация, перезарядка, получение сырых тиков).
* `timer.c` — Реализация работы с системными регистрами таймера AArch64.

## Используемые системные регистры процессора

Драйвер не работает напрямую с памятью (MMIO), а использует высокоскоростные сопроцессорные инструкции доступа к регистрам ядра:

* `CNTFRQ_EL0` — Регистр частоты встроенного таймера. Инициализируется на этапе BootROM/U-Boot (на платах RK3588 обычно составляет **24 МГц**).
* `CNTP_TVAL_EL0` — Регистр значения таймера обратного отсчета (Timer Value). При записи значения начинает аппаратно декрементироваться. При достижении нуля генерирует прерывание **GIC IRQ ID 30**.
* `CNTP_CTL_EL0` — Регистр управления (Control). Отвечает за включение таймера и маскирование его прерываний.
* `CNTPCT_EL0` — Регистр физического счетчика времени (Physical Count). Непрерывно инкрементируется с момента включения SoC.

## Архитектурные функции

### Инициализация (`core_timer_init`)
Принимает требуемую частоту системного тика в Герцах (например, `100` для получения тиков каждые 10 мс). 
Формула расчета интервала:
$$\text{ticks} = \frac{\text{CNTFRQ\_EL0}}{\text{hz}}$$
Полученное значение записывается в `CNTP_TVAL_EL0`, после чего прерывание таймера маршрутизируется контроллером GICv3 на текущее ядро процессора.

### Получение точного времени (`core_timer_get_ticks`)
Считывает значение `CNTPCT_EL0`. Используется для создания точных, неблокирующих процессор микросекундных задержек (`delay_us`), замеряя дельту между тиками счетчика:

```c
uint64_t start = core_timer_get_ticks();
while ((core_timer_get_ticks() - start) < required_ticks);
```
