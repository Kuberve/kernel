# UART Driver Subsystem — Kuberve Microkernel

Этот модуль предоставляет легковесную, аппаратно-независимую подсистему форматированного текстового вывода (`printk`) для микроядра **Kuberve**.

## Архитектура абстракции

Для обеспечения переносимости ядра между эмуляторами и реальным железом, подсистема разделена на два уровня:

1. **Hardware Abstraction Layer (HAL / Аппаратный уровень):** Физические драйверы конкретных чипов UART. Они реализуют только базовую отправку символа `uart_putc` и строки `uart_puts`.
2. **Core Kernel Space (Уровень ядра):** Универсальный парсер строк `printk`, который работает поверх выбранного HAL и ничего не знает об адресах регистров.

## Структура файлов модуля

* `uart.h` — Общий интерфейс ввода-вывода символов. Объявляет функции `uart_putc` и `uart_puts`.
* `printk.h` / `printk.c` — Реализация ядерного аналога функции `printf`. Использует встроенные макросы компилятора `__builtin_va_list` для работы без стандартной библиотеки Си (`-nostdlib`).
* `pl011.c` — Драйвер для контроллера **ARM PrimeCell PL011** (базовый адрес `0x09000000`), используемый при тестировании в QEMU на машине `virt`.
* `rk16550.c` — Драйвер для встроенного контроллера **Synopsys DesignWare / 16550 UART** чипа Rockchip RK3588 (базовый адрес `0xFEB50000`), используемый для реальной платы Radxa Rock 5 ITX.

## Поддерживаемые спецификаторы формата `printk`

| Спецификатор | Тип данных | Описание | Пример вывода |
| :---: | :--- | :--- | :--- |
| `%s` | `char *` | Вывод строки (null-terminated) | `Kuberve` |
| `%c` | `char` | Вывод одиночного ASCII-символа | `A` |
| `%d` | `int64_t` | Знаковое десятичное число | `-123456` |
| `%x` | `uint64_t` | Шестнадцатеричное число (нижний регистр) | `abcdef` |
| `%p` | `void *` | Указатель / Физический адрес памяти | `0x48000000` |
| `%%` | — | Экранирование символа процента | `%` |

## Управление сборкой через `Makefile`

Выбор конкретного аппаратного драйвера контролируется переменной окружения `BOARD` на этапе вызова `make`. Система сборки автоматически исключает ненужный драйвер из объектных файлов, предотвращая конфликты линковщика:

* **Для тестирования в эмуляторе (PL011):**
  ```bash
  make run
  # или компиляция: make BOARD=qemu
  ```
* **Для деплоя на реальную плату Radxa (16550):**
  ```bash
  make BOARD=radxa
  ```
